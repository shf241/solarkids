# SolarKids 成员4独立部分完成计划与验收标准

## 一、文档目的

本文档用于指导成员4在不等待成员2（UI 与响应式）和成员3（Canvas 动画）的情况下，完成当前可以独立开发、独立测试和独立提交的工作。

计划遵循以下原则：

1. 先完成课程要求中的必做项，再完成优先加分项，最后考虑小游戏。
2. 独立阶段不修改成员2、成员3负责的核心文件。
3. 数据模块和游戏逻辑通过清晰接口与 UI、Canvas 解耦。
4. 每项工作都必须有代码、测试结果或文档记录作为验收证据。
5. 未实际执行的测试不得填写为“通过”。
6. 独立阶段完成不等于项目最终完成；UI、Canvas 接入和整体验收仍需在其他成员代码合并后进行。

## 四、模块接口约定

本节用于提前固定数据边界，避免后续整合时反复修改。若团队已有正式接口，以团队接口为准，并在测试记录中说明调整原因。

### 4.1 LocalStorage 存储键

建议只使用一个带版本号的根键：

```text
solarkids.user-state.v1
```

使用单一根键的原因：

- 便于整体读取、导出、重置和升级。
- 避免多个零散键出现部分成功、部分失败。
- 版本号可以支持后续数据结构迁移。

### 4.2 用户状态结构

建议 TypeScript 结构：

```ts
type LanguageCode = "zh-CN" | "en";

interface LearningProgress {
  visitedPlanetIds: string[];
  completedTaskIds: string[];
}

interface GameRecord {
  playCount: number;
  successCount: number;
  bestScore: number;
  lastScore: number;
}

interface SolarKidsUserState {
  version: 1;
  language: LanguageCode;
  skinId: string;
  learningProgress: LearningProgress;
  gameRecord: GameRecord;
}
```

建议默认值：

```json
{
  "version": 1,
  "language": "zh-CN",
  "skinId": "default",
  "learningProgress": {
    "visitedPlanetIds": [],
    "completedTaskIds": []
  },
  "gameRecord": {
    "playCount": 0,
    "successCount": 0,
    "bestScore": 0,
    "lastScore": 0
  }
}
```

约束：

1. `language` 只能是 `zh-CN` 或 `en`。
2. `skinId` 只保存皮肤标识，不耦合成员2的 CSS 类名或资源路径。
3. 行星和任务使用稳定 ID，不保存中文名称。
4. 次数和分数必须是大于等于 0 的有限数值。
5. 对重复访问的行星 ID 去重。
6. 读取旧数据、损坏 JSON 或字段缺失时，返回经过修复的有效状态。
7. 不保存 DOM、Canvas 对象、函数或图片对象。

### 4.3 Storage 模块公开接口

建议只公开必要接口：

```ts
loadUserState(): SolarKidsUserState
saveUserState(state: SolarKidsUserState): void
updateUserState(patch: Partial<SolarKidsUserState>): SolarKidsUserState
setLanguage(language: LanguageCode): SolarKidsUserState
setSkin(skinId: string): SolarKidsUserState
markPlanetVisited(planetId: string): SolarKidsUserState
saveGameResult(score: number, success: boolean): SolarKidsUserState
resetUserState(): SolarKidsUserState
```

实现要求：

1. 业务代码不直接调用散落的 `localStorage.setItem`。
2. Storage 对象应可注入或替换，使自动测试可以使用内存模拟对象。
3. 每次写入前先规范化数据。
4. 浏览器禁止存储或容量异常时，不让应用主流程崩溃。
5. 异常回退行为必须有测试，且在测试记录中说明。

### 4.4 多语言 JSON 结构

建议使用“语言在第一层、相同文案键在第二层”的结构：

```json
{
  "zh-CN": {
    "app.title": "SolarKids",
    "action.start": "开始探索",
    "action.pause": "暂停",
    "action.play": "继续",
    "action.reset": "重置"
  },
  "en": {
    "app.title": "SolarKids",
    "action.start": "Start Exploring",
    "action.pause": "Pause",
    "action.play": "Play",
    "action.reset": "Reset"
  }
}
```

文案范围至少覆盖：

- 首页标题与开始按钮。
- 播放、暂停、放大、缩小、视角、返回、关闭和重置。
- 设置、语言、皮肤和小游戏入口。
- 八大行星名称。
- 行星关键词和儿童科普短句。
- 游戏提示、成功反馈和重试提示。
- 数据重置确认文案。

文案验收规则：

1. 中英文键集合完全一致。
2. 不允许空字符串。
3. 英文面向 7-12 岁儿童，使用短句和常用词。
4. 不在 TypeScript 中重复硬编码已经进入词典的界面文案。
5. 缺失键时回退到中文或明确显示键名，不能返回 `undefined`。
6. JSON 必须能被标准解析器直接读取。

### 4.5 多语言模块接口

建议公开以下接口：

```ts
getLanguage(): LanguageCode
setLanguage(language: LanguageCode): void
translate(key: string, language?: LanguageCode): string
hasTranslation(key: string, language?: LanguageCode): boolean
```

与成员2对接时，UI 只负责：

1. 调用 `setLanguage`。
2. 根据文案键调用 `translate`。
3. 重新渲染可见文本。

UI 不应自行保存第二份语言状态。

### 4.6 小游戏纯逻辑边界

独立阶段只实现与 Canvas 无关的确定性逻辑：

- 游戏初始状态。
- 行星默认位置。
- 拖动后的目标位置输入。
- 相对默认轨道的偏移量。
- 用于儿童提示的变化等级。
- 成功条件、分数和重置。
- 游戏结果写入存储模块。

建议状态：

```ts
interface Point {
  x: number;
  y: number;
}

interface OrbitGameState {
  planetId: string;
  startPosition: Point;
  currentPosition: Point;
  displacement: number;
  changeLevel: "stable" | "small" | "large";
  score: number;
  completed: boolean;
}
```

建议纯函数：

```ts
createGameState(planetId: string, startPosition: Point): OrbitGameState
movePlanet(state: OrbitGameState, target: Point): OrbitGameState
resetGame(state: OrbitGameState): OrbitGameState
finishGame(state: OrbitGameState): GameResult
```

科学表达限制：

1. 如果没有真实引力模型，不得在界面或答辩中宣称“精确模拟真实引力”。
2. 独立阶段应表述为“根据拖动距离展示轨道变化的教学近似”。
3. 变化阈值和评分规则必须写入代码常量并有测试。
4. 成员3接入后再决定如何把逻辑结果映射到 Canvas 轨道视觉。
