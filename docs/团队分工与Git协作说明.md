# SolarKids 天体运行少儿教学软件团队分工与 Git 协作说明

## 一、项目目标

SolarKids 是一个面向儿童的 Web 天体运行教学软件，核心目标是“能看懂、能互动、能学习”。

项目需要满足以下要求：

- 使用 HTML5、CSS3、JavaScript、TypeScript、Canvas、SVG
- 使用 LocalStorage 和 JSON 进行数据存储
- 支持 PC、iPad、手机响应式布局
- 支持缩放和视角切换
- 动画平滑、自然，避免视觉疲劳
- 禁止使用 Three.js、Unity WebGL、Babylon.js 直接替代核心实现
- 提交用户操作流程图
- 提交 AI 协同开发说明书
- 使用 Git 管理版本

## 二、GitHub 仓库

## 四、每个人第一次操作流程

1. 克隆仓库：

```bash
git clone https://github.com/shf241/solarkids.git
```

2. 进入项目：

```bash
cd solarkids
```

3. 从最新 `dev` 更新并切换到自己的分支，例如 UI 负责人：

```bash
git switch dev
git pull origin dev
git switch feature/ui-responsive
```

4. 已有功能分支在继续开发前，先把最新 `dev` 合入：

```bash
git merge dev
```

5. 修改完成后提交：

```bash
git add <本次实际修改的文件>
git commit -m "feat: 完成某某功能"
git push origin <自己的分支名>
```

## 五、分支管理规则

- `main`：最终稳定版本，只放可以提交给老师的版本。
- `dev`：日常整合版本，用来合并大家阶段性成果。
- `feature/product-flow`：产品流程、用户分析、交互文档。
- `feature/eclipse-magnetic`：日食、月食、太阳磁场和地球磁场。
- `feature/ui-responsive`：UI 视觉、SVG 素材、响应式界面。
- `feature/canvas-orbit`：天体运行、哈雷彗星、交互和视角切换。
- `feature/storage-game`：LocalStorage、多语言和小游戏逻辑。
- `feature/member4-integration`：太阳风、成员4功能整合与验收记录。

协作规则：

1. 每个人只 push 到自己的 `feature/*` 分支。
2. 不要直接 push 到 `main`。
3. 新分支必须以最新 `dev` 为起点，旧分支不能直接覆盖新版文件。
4. 需要合并到 `dev` 时，先在群里说明完成内容和修改文件。
5. 修复已合并功能时，应从最新 `dev` 新建修复分支；经确认后再合并或推送到 `dev`。
6. 如果两个人都要改 `src/main.ts`、共享场景工具或同一份文档，必须先沟通。
7. 合并后其他分支不会自动更新，需要主动合并最新 `dev`。
8. 最终测试通过后，再由负责人把 `dev` 合并到 `main`。
9. 最终提交 zip 包时，打包 `main` 分支的稳定版本。

## 六、提交信息格式

功能类：

```bash
git commit -m "feat: 添加行星信息展示"
```

修复类：

```bash
git commit -m "fix: 修复手机端按钮重叠问题"
```

文档类：

```bash
git commit -m "docs: 补充用户操作流程图"
```

样式类：

```bash
git commit -m "style: 调整儿童化界面配色"
```

优化类：

```bash
git commit -m "perf: 优化 Canvas 动画渲染"
```

每个人的 Git 提交记录都会体现自己的工作量，所以不要最后一天一次性提交。建议每完成一个小功能就 commit 一次。

## 七、AI 开发说明书分摊

AI 开发说明书不是只由一个人写，成员4负责最终整合，但每个人都要补充自己负责的部分。

- 成员1：产品设计、用户分析、日月食和磁场模块实现与修改过程。
- 成员2：视觉风格生成过程、UI 优化过程、儿童视觉体验考虑。
- 成员3：天体运行、哈雷彗星、交互视角、Canvas 技术与性能优化过程。
- 成员4：太阳风、数据存储、多语言、小游戏、测试整合与最终 AI 使用总结。

说明书中需要体现：

- AI 生成了什么内容
- 学生修改了什么内容
- 为什么这样设计
- 如何优化儿童用户体验
- 哪些地方体现了独立思考和产品判断

## 八、功能交付标准

每个模块合并前至少需要满足：

- 功能入口能够从主界面正常进入和返回。
- 播放、暂停、速度和换肤等公共控制不互相冲突。
- PC 和手机尺寸下主要内容不被信息卡或控制栏遮挡。
- TypeScript 类型检查和生产构建通过。
- 修改者在自己的 AI 开发记录中说明 AI 生成内容和人工调整内容。

## 九、最终验收清单

提交前需要统一检查：

- 是否包含 HTML5、CSS3、JavaScript、TypeScript、Canvas、SVG
- 是否使用 LocalStorage

- 是否支持 PC、iPad、手机响应式布局
- 是否支持缩放和视角切换
