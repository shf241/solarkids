# SolarKids 天体运行少儿教学软件团队分工与 Git 协作说明

## 一、项目目标

SolarKids 是一个面向儿童的 Web 天体运行教学软件，核心目标是“能看懂、能互动、能学习”。

项目需要满足以下要求：

- 使用 HTML5、CSS3、JavaScript、TypeScript、Canvas、SVG
- 使用 LocalStorage 和 JSON 进行数据存储
- 支持 PC、iPad、手机响应式布局
- 支持缩放和视角切换
- 动画平滑、自然，避免视觉疲劳
- 禁止使用 Three.js、Unity WebGL、Babylon.js 直接替代核心实现
- 提交用户操作流程图
- 提交 AI 协同开发说明书
- 使用 Git 管理版本

## 二、GitHub 仓库

仓库地址：

https://github.com/shf241/solarkids

## 三、成员分工

### 成员1：产品与交互负责人

对应分支：

`feature/product-flow`

主要负责：

1. 用户分析：儿童用户特点、学习场景、操作习惯。
2. 信息结构设计：主界面、天体知识、互动模式、设置页面等结构。
3. 用户操作流程图：保证主要功能操作步骤不超过 5 步。
4. 儿童友好体验设计：按钮、提示语、引导流程、低门槛操作。
5. AI 开发说明书中的产品设计过程、用户分析过程、设计决策说明。

主要修改位置：

- `docs/用户操作流程图.md`
- `docs/产品设计说明.md`
- `docs/AI开发说明书.md`

交付内容：

- 用户操作流程图
- 页面信息架构图
- 儿童用户分析
- 交互说明文档

提交到：

`feature/product-flow`

### 成员2：UI 视觉与响应式负责人

6. AI 开发说明书中的视觉设计过程、UI 优化过程、儿童视觉考虑。

提交到：

`feature/ui-responsive`

## 四、每个人第一次操作流程

1. 克隆仓库：

```bash
git clone https://github.com/shf241/solarkids.git
```

2. 进入项目：

```bash
cd solarkids
```

3. 切换到自己的分支，例如 UI 负责人：

```bash
git checkout feature/ui-responsive
```

4. 开发前先更新：

```bash
git pull
```

5. 修改完成后提交：

```bash
git add .
git commit -m "feat: 完成某某功能"
git push
```

## 五、分支管理规则

- `main`：最终稳定版本，只放可以提交给老师的版本。
- `dev`：日常整合版本，用来合并大家阶段性成果。
- `feature/product-flow`：产品流程、用户分析、交互文档。
- `feature/ui-responsive`：UI 视觉、SVG 素材、响应式界面。
- `feature/canvas-orbit`：Canvas 天体运行、彗星轨道、动画渲染。
- `feature/storage-game`：LocalStorage、多语言、小游戏、测试整合。

协作规则：

1. 每个人只 push 到自己的 `feature/*` 分支。
2. 不要直接 push 到 `main`。
3. 需要合并到 `dev` 时，先在群里说明自己完成了什么。
4. 合并前说明自己修改了哪些文件，避免冲突。
5. 如果两个人都要改同一个文件，比如 `src/main.ts` 或 `docs/AI开发说明书.md`，先在群里沟通。
6. 最终测试通过后，再由负责人把 `dev` 合并到 `main`。
7. 最终提交 zip 包时，打包 `main` 分支的稳定版本。

## 六、提交信息格式

功能类：

```bash
git commit -m "feat: 添加行星信息展示"
```

修复类：

```bash
git commit -m "fix: 修复手机端按钮重叠问题"
```

文档类：

```bash
git commit -m "docs: 补充用户操作流程图"
```

样式类：

```bash
git commit -m "style: 调整儿童化界面配色"
```

优化类：

```bash
git commit -m "perf: 优化 Canvas 动画渲染"
```

每个人的 Git 提交记录都会体现自己的工作量，所以不要最后一天一次性提交。建议每完成一个小功能就 commit 一次。

## 七、AI 开发说明书分摊

AI 开发说明书不是只由一个人写，成员4负责最终整合，但每个人都要补充自己负责的部分。

- 成员1：产品设计过程、用户分析过程、交互设计决策。
- 成员2：视觉风格生成过程、UI 优化过程、儿童视觉体验考虑。
- 成员3：Canvas 动画生成过程、技术实现过程、性能优化过程。
- 成员4：数据存储、多语言、小游戏、测试整合、最终 AI 使用总结。

说明书中需要体现：

- AI 生成了什么内容
- 学生修改了什么内容
- 为什么这样设计
- 如何优化儿童用户体验
- 哪些地方体现了独立思考和产品判断

## 八、功能优先级

### 必做功能

- 太阳系天体运行
- 行星信息展示
- 缩放和视角切换
- Canvas 核心动画
- SVG 图形元素
- LocalStorage 数据保存
- JSON 数据读取
- PC、iPad、手机响应式适配
- 用户操作流程图
- AI 协同开发说明书

### 优先加分项

- 彗星多条轨道模拟
- 动态彗尾效果
- 中英文多语言切换
- 天体换肤功能

### 有时间再冲刺

- 太阳风与地球磁场互动
- 拖动行星观察引力和轨道变化小游戏

原则：先保证基础功能完整，再做加分项。不要为了加分项影响主功能稳定。

## 九、最终验收清单

提交前需要统一检查：

- 是否包含 HTML5、CSS3、JavaScript、TypeScript、Canvas、SVG
- 是否使用 LocalStorage
- 是否使用 JSON 数据
- 是否支持 PC、iPad、手机响应式布局
- 是否支持缩放和视角切换
- 主要功能是否 5 步以内可以完成
- 界面是否适合儿童理解和操作
- 动画是否平滑、不过度闪烁
- 是否有用户操作流程图
- 是否有 AI 协同开发说明书
- 是否有测试记录
- Git 提交记录是否能体现每个人的工作
- `main` 分支是否是最终稳定版本
- zip 包是否能正常打开和运行

## 十、阶段安排

### 第1阶段：确定方案

完成用户分析、功能列表、页面结构、流程图、技术选型。

### 第2阶段：完成基础版本

实现太阳系运行、基础 UI、响应式布局、行星信息展示。

### 第3阶段：完善互动功能

加入缩放、视角切换、换肤、多语言、LocalStorage。

### 第4阶段：冲刺加分项

实现彗星轨道、动态彗尾、太阳风与地球磁场、拖动行星小游戏。

### 第5阶段：测试与提交

统一检查 PC、iPad、手机显示效果，整理 AI 开发说明书，打包 zip，准备答辩。
