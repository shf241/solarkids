## 六、已发现的接口问题

### 6.1 皮肤ID不一致

成员4默认状态当前使用：

```text
default
```

现有UI实际使用：

```text
cartoon
realistic
```

处理方案：

1. 将Storage默认 `skinId` 改为 `cartoon`。
2. 启动时先读取Storage，再加载并应用对应皮肤。
3. 如果保存的ID不在 `skins.json` 中，回退 `cartoon`。
4. 换肤成功后调用 `setSkin(skinId)`。
5. 增加有效皮肤、未知皮肤和刷新恢复测试。

### 6.2 多语言JSON浏览器加载方式

当前多语言模块直接通过TypeScript导入JSON。项目没有Vite/Webpack，最终页面直接加载编译后的原生浏览器模块，这种方式存在浏览器JSON模块兼容风险。

处理方案：

1. 保留 `src/data/language.json` 作为唯一词典数据源。
2. 增加异步 `loadTranslationData()`，通过 `fetch` 加载JSON。
3. 应用启动时先初始化词典，再绑定语言按钮。
4. 加载失败时使用最小中文回退词典，不阻止Canvas启动。
5. 自动测试继续直接解析JSON，浏览器测试验证真实 `fetch`。

### 6.3 小游戏距离单位不统一

当前纯逻辑阈值使用5和60单位。若直接传入屏幕像素，手机和PC上的实际难度不同。

处理方案：

1. Canvas场景将指针坐标转换为标准化游戏坐标。
2. 建议使用 `min(viewport.width, viewport.height)` 归一化到1000单位。
3. 纯逻辑继续只接收标准化坐标，不感知屏幕尺寸。
4. 增加手机和桌面同等拖动比例得到相同结果的测试。

### 6.4 行星数据重复

现有 `solarSystemPreview.ts` 内硬编码中文行星名称和说明，成员4词典中也有同类数据。

处理方案：

1. 稳定行星ID继续使用 `mercury` 至 `neptune`。
2. UI显示文案逐步改为通过词典键读取。
3. 轨道、半径和速度等物理/绘制参数后续由成员3维护在行星JSON中。
4. 成员4不复制成员3的轨道参数。

### 6.5 共享文件冲突

高冲突文件：

- `src/main.ts`
- `src/canvas/controlBridge.ts`
- `index.html`
- `src/style.css`
- `docs/测试记录.md`
- `package.json`

处理方案：

1. 成员4的大部分实现放入独立文件。
2. 每完成一个模块，最后才对共享文件做小范围接线。
3. 修改共享文件前在群里说明具体行和事件名。
4. 每次接线前同步最新 `dev`，接线后运行完整检查。

当前成员4的太阳风和小游戏开发不需要新增网络美术素材：
