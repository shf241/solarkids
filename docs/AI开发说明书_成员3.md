## 一、产品设计过程

### 1.1 负责内容

本人主要负责：

- 搭建公共 Canvas 动画运行时，统一管理动画时钟、播放状态、场景、图层、相机和天体状态。
- 实现太阳、月球和八大行星的自转、公转、轨道、球面纹理、光照及土星环效果。
- 实现太阳系总览、天体点击、百科面板、通用探访和地球地表观察视角。
- 实现哈雷彗星高偏心率轨道、开普勒运动和随日彗距离变化的动态彗尾。
- 实现鼠标、触摸、滚轮、键盘和 Arcball 交互，并处理背景平移与球体旋转的手势冲突。
- 为成员1的日月食、磁场模块和成员4的太阳风等模块提供稳定的场景注册、时间倍率和公开天体状态接口。
- 编写并维护成员3相关接口说明、测试记录和 AI 开发说明。

### 1.2 功能目标

- 在不引入 Three.js 或 WebGL 的前提下，使用 Canvas 2D 表现具有球体感的动态太阳系。
- 通过真实天文参数保持行星公转周期、相对轨道距离和相对半径的基本关系，同时保证手机端可见和可操作。
- 让所有场景共享一个长期运行的 `requestAnimationFrame`，统一播放、暂停、速度倍率和资源清理。
- 使儿童能够通过总览、探访和地表视角理解天体运动、行星外观及观察位置变化。
- 保证卡通和写实模式使用相同的运动与交互逻辑，只替换对应视觉素材。
- 为团队其他专题提供只读、稳定的天体状态和场景接口，减少多人修改核心文件造成的冲突。

### 1.3 初步设计方案

以下方案由学生确定，AI 根据方案辅助生成和修改代码：

- 运行架构：建立 `CanvasRuntime`，由动画控制器统一调用当前场景和叠加图层的 `update()`、`render()`。
- 场景划分：太阳系总览使用 `solar-system` 场景，哈雷彗星使用独立 `comet` 场景，日月食和磁场由成员1注册为独立专题场景。
- 天体运动：使用真实公转周期推进轨道角度，使用真实自转周期比例推进纹理经度偏移。
- 球面渲染：将 2:1 等距柱状投影纹理反向采样到圆形球面，结合球面法线和光照方向计算明暗。
- 显示比例：真实 AU 和地球半径比作为输入，通过统一幂函数压缩为可视轨道距离和天体半径。
- 交互方式：总览拖动使用 Arcball 旋转太阳系，`Shift + 拖动`平移，滚轮锚点缩放；探访时球体内拖动旋转天体，背景拖动平移画面。
- 地表视角：使用天体三维黄道坐标、黄赤交角、观察纬度和当地恒星时计算高度角、方位角。
- 彗星模拟：用开普勒方程计算高偏心率轨道位置和速度，彗尾始终背离太阳并随距离改变。

## 二、用户分析过程

### 2.1 目标用户

- 主要用户：7—12 岁儿童，也可用于教师课堂演示或家长辅助讲解。
- 知识基础：认识太阳、地球和常见行星，但未必理解轨道周期、自转、公转、视角变换和彗星速度变化。
- 操作设备：电脑、iPad、手机浏览器。
- 使用特点：更容易通过运动、颜色、拖动和即时反馈理解概念，不适合阅读大量公式和长篇文字。

### 2.2 用户需求

- 行星必须明显位于对应轨道上，运动方向和相对速度应保持稳定。
- 行星大小和轨道间距既要体现基本物理关系，又不能小到无法看清或点击。
- 用户点击天体后应立即看到名称和基础百科，并能进一步“探访”观察细节。
- 探访过程应停止无关天体运动，避免放大单颗天体时背景仍按太阳系逻辑高速运动。
- 鼠标在球体上拖动应旋转球体，在背景上拖动应移动画面，两种手势不能相互抢占。
- 卡通和写实皮肤的功能、运动、探访和手势应完全一致。
- 手机端应支持单指、双指和安全区域，控制栏与信息面板不能遮挡主要画面。
- 播放、暂停、速度、缩放、重置和场景入口应在所有场景中保持可预测的行为。

### 2.3 可能出现的问题

- 真实太阳系绝对比例会让大部分行星接近像素点，无法完成儿童教学和点击操作。
- 直接左右移动矩形纹理只能产生平面滚动感，不能形成真正的球面压缩。
- 直接旋转圆形图片无法表现天体自转，且会让固定光照方向跟随纹理错误转动。
- 高分辨率纹理逐像素采样可能降低移动端帧率。
- 土星环需要区分球体前后遮挡，单张平面图片难以支持全方位观察。
- 总览旋转、相机平移、球体旋转和移动端双指手势容易产生输入冲突。
- 地表视角若直接使用二维总览坐标，所有天体会被压在同一轨迹上。
- 专题场景若各自创建动画循环，会造成重复更新、播放状态不一致和资源泄漏。
- 团队不同模块对“卡通/写实”和“SVG/PNG”的类型命名不同，直接覆盖会破坏其他成员素材逻辑。

## 三、AI 生成内容

### 3.1 AI 使用方式

1. 向 AI 说明本人负责的模块、课程要求、儿童用户特点和团队分工边界。
2. 要求 AI 先检查仓库、分支、现有静态预览、UI 事件和公共接口，再提出实现方案。
3. 先搭建最小公共动画骨架，通过控制台验证运行时、动画状态、相机和天体状态。
4. 按模块1、模块6、模块5的顺序逐步生成或修改 TypeScript 和 Canvas 代码。
5. 在浏览器中观察轨道、速度、球面、光照、探访和手势效果，向 AI 描述具体问题并要求定位修改。
6. 使用 TypeScript 编译、断言脚本、素材路径扫描和 `git diff --check` 检查代码。
7. 对比团队成员分支，保留其他成员原有实现，通过兼容层解决接口差异。
8. 按素材、公共接口、功能模块、UI 集成和文档拆分 Git 提交，经人工确认后提交 PR。

### 4.2 具体修改说明

#### 4.2.1 重构太阳系运动与显示比例

- 原始问题：行星视觉位置与轨道不一致，速度使用统一动画步长，天体大小和轨道距离主要依赖手工参数。
- 发现方式：在浏览器播放总览，并通过控制台比较动画前后的地球轨道角、自转角和月球相对距离。
- 涉及文件：`src/canvas/solarSystemScene.ts`、`src/ui/solarSystemPreview.ts`
- 涉及模块：模块1公转、自转和轨道显示
- 涉及函数或接口：轨道状态更新、`runtime.world.setBody()`、`displayPosition`、半径与距离映射
- 学生修改内容：
  1. 明确要求行星必须位于对应轨道上，并按真实公转周期保持相对速度。
  2. 使用真实 AU 和地球半径比作为数据输入。
  3. 分别为轨道距离和天体半径设计统一幂函数压缩，而非逐颗手工调整。
  4. 为月球建立 `parentId = earth` 的父子关系。
  5. 将逻辑坐标和响应式显示坐标分开，避免窄屏投影后点击或聚焦错位。
- 修改原因：保持核心物理关系，同时满足儿童教学、移动端显示和点击操作。
- 修改结果：八大行星沿对应轨道运行，相对速度、大小和内外行星层次更加合理。
- 验证方式：编译后播放、暂停和加速，检查轨道角、自转角、月球距离、轨道 hover 和多尺寸布局。

#### 4.2.2 从平面贴图改为动态纹理球

- 原始问题：直接横向移动矩形图片仍像平面滚动；直接旋转圆形图片无法体现球体自转；中轴、箭头和外围光膜过于抽象。
- 发现方式：分别观察地球写实试点、自转箭头方案和高倍探访画面。
- 涉及文件：`src/canvas/EquirectangularPlanetRenderer.ts`、`src/canvas/solarSystemScene.ts`
- 涉及模块：模块1球面和自转渲染
- 涉及函数或接口：经纬度反向采样、`rotationAngle`、`textureOffset`、法线光照、离屏缓存
- 学生修改内容：
  1. 否定只移动图片和直接旋转图片的方案。
  2. 要求从屏幕球面坐标反算纹理经纬度，使边缘自然压缩。
  3. 使用球面法线与太阳方向点积计算亮面和暗面，光照不跟随纹理旋转。
  4. 删除中轴线、圆形箭头和外围薄膜。
  5. 使用低分辨率离屏 Canvas、采样缓存和动态输出尺寸控制性能。
- 修改原因：让自转来自表面经度变化，同时保持光照和球体形状稳定。
- 修改结果：卡通和写实天体均以纹理球形式显示，自转、光照和手动观察方向相互独立。
- 验证方式：进入地球及其他天体探访，观察大陆或表面特征是否随拖动和时间正确移动，并检查边缘和昼夜明暗。

#### 4.2.3 完善探访、Arcball 和手势分流

- 原始问题：初版聚焦尺寸过小；拖动方式只是累加水平/垂直旋转角；背景平移后球体命中位置仍固定在画布中心。
- 发现方式：探访地球后拖动球面和背景，再尝试从平移后的球体位置重新抓取。
- 涉及文件：`src/canvas/CanvasInteractions.ts`、`src/canvas/Camera2D.ts`、`src/canvas/solarSystemScene.ts`
- 涉及模块：模块6视角和输入交互
- 涉及函数或接口：Arcball 球面向量、四元数、Pointer Capture、`worldToScreen()`、聚焦插值
- 学生修改内容：
  1. 将探访目标逐步放大到画布短边约55%。
  2. 探访时隐藏其他天体和轨道，并冻结公转与自动自转。
  3. 使用按下点和移动点对应的球面向量计算四元数，使抓取点跟随指针。
  4. 使用相机变换后的真实屏幕中心和半径判断球体命中。
  5. 将球体内拖动、背景拖动、总览 Arcball、`Shift` 平移和双指缩放划分为互斥状态。
- 修改原因：使电脑和移动端操作符合“抓住球体转动”的直觉，并避免场景手势相互冲突。
- 修改结果：用户可在平移和缩放后继续旋转目标天体，背景操作不会误转球体。
- 验证方式：反复执行探访、背景平移、球体旋转、滚轮缩放、返回总览和移动端单/双指操作。

#### 4.2.4 建立地表观察和哈雷彗星物理计算

- 原始问题：地表视角仍像俯视太阳系；哈雷彗星若匀速沿椭圆运动，无法表现近日点加速和彗尾变化。
- 发现方式：进入地表视角和彗星场景，比较天体轨迹、速度及彗尾方向。
- 涉及文件：`EarthObserverView.ts`、`solarSystemScene.ts`、`cometScene.ts`
- 涉及模块：模块6地表视角、模块5哈雷彗星
- 涉及函数或接口：黄道转赤道、赤道转地平、Newton 迭代、开普勒方程、日彗距离
- 学生修改内容：
  1. 地表模式改为地平线、大气层和观察者天空，而非俯视轨道。
  2. 加入轨道倾角、升交点、黄赤交角、观察纬度和当地恒星时。
  3. 彗星使用真实高偏心率参数求解位置和速度。
  4. 彗尾始终背离太阳，长度、宽度、亮度和颜色随日彗距离连续变化。
  5. 物理轨道和视觉轨道分别保存，避免近日点与太阳贴图重叠。
- 修改原因：保留儿童可以观察的核心天文关系，同时避免真实绝对比例导致画面不可用。
- 修改结果：地表天体具有不同天空轨迹，彗星具有明显的变速和彗尾活动变化。
- 验证方式：改变时间倍率和观察方向，检查地平线可见性；比较彗星近日点、远日点速度和彗尾状态。

#### 4.2.5 处理团队接口与素材兼容

- 原始问题：成员1专题场景沿用 `SkinType = 'svg' | 'png'`，成员3球面纹理使用 `cartoon/realistic`；直接修改同一类型会让日月食和磁场加载错误素材。
- 发现方式：合并最新 `dev` 后检查专题场景素材路径、类型编译和运行结果。
- 涉及文件：`src/ui/assetLoader.ts`、`src/main.ts`
- 涉及模块：团队素材接口和场景集成
- 涉及函数或接口：`SkinType`、`RenderSkinType`、`preloadAllAssets()`、`getCachedImage()`、`registerMember1Scenes()`
- 学生修改内容：
  1. 保留成员1的日月食、磁场、场景注册和公共绘制文件不变。
  2. 将成员3球面模式定义为独立 `RenderSkinType`。
  3. 在共享加载器中分别预加载和缓存 SVG/PNG 专题素材与球面纹理。

- 验证方式：比较成员1场景文件与 `dev`、检查 SVG/PNG 和球面素材 HTTP 读取、执行严格编译和 Git 差异检查。

### 5.1 测试方式

- 逐一探访太阳、月球和八大行星，检查聚焦尺寸、冻结、球体旋转、背景平移和返回流程。
- 进入地表视角，检查地平线、大气层、天空轨迹、观察方向和地平线以下隐藏。
- 进入哈雷彗星场景，检查变速、彗尾方向、距离状态、轨道开关和信息面板。

- 执行 TypeScript 构建、逻辑断言、素材路径扫描和 `git diff --check`。

### 5.2 体验问题与优化

| 体验问题 | 优化方式 | 最终效果 |
| --- | --- | --- |
| 行星、轨道和大小比例主要依赖手工参数 | 使用真实参数输入和统一幂函数压缩 | 保留内外行星层次，同时所有天体可见可点。 |
| 自转箭头、中轴和薄膜影响真实感 | 改为纹理经度偏移和固定球面光照 | 自转直接体现在表面特征移动。 |
| 高倍探访纹理模糊或采样成本过高 | 原纹理降采样、动态离屏尺寸和经纬法线缓存 | 在清晰度和移动端性能之间取得平衡。 |
| 探访时其他天体继续运动 | 隐藏无关天体并冻结场景累计时间 | 用户可以专注观察目标，返回后不发生时间跳跃。 |
| 拖动背景后无法继续旋转球体 | 使用相机变换后的屏幕位置重新命中 | 平移后仍能自然抓取球体。 |
| 卡通星空装饰星比行星更大 | 换用小星点卡通背景并缩细虚线轨道 | 背景不再抢夺天体视觉重点。 |
| 地表视角天体轨迹重合 | 使用三维轨道和完整坐标转换 | 不同天体具有不同高度和方向。 |
| 哈雷彗星匀速、彗尾固定 | 使用开普勒运动和距离驱动彗尾 | 近日点和远日点差异明显。 |
| 团队素材类型命名冲突 | 分离 `SkinType` 与 `RenderSkinType` | 成员1和成员3素材互不覆盖。 |

### 5.3 优化结果

- 操作清晰度：总览、地表、探访和专题入口职责明确，六个入口保持互斥高亮。
- 动画可理解性：行星沿轨道按相对周期运行，球面自转、昼夜光照和彗星变速均可直接观察。
- 页面美观度：写实和卡通统一使用纹理球、星空背景、虚线轨道和分层土星环。
- 交互自然度：总览、背景、球体、单指和双指手势被明确分流，拖动后不会误选天体。
- 移动端适配：DPR、动态视口、安全区域和触摸事件均由公共运行时或交互控制器统一处理。
- 运行稳定性：所有主场景共用一个动画循环，退出时统一解绑事件和资源。
- 团队兼容性：专题场景通过公开运行时和素材兼容层接入，不直接修改成员3内部状态或覆盖其他成员素材。

## 六、设计决策说明

### 6.1 主要设计决策

| 设计问题 | 最终选择 | 选择原因 |
| --- | --- | --- |
| 是否引入 Three.js/WebGL | 继续使用 Canvas 2D 和离屏缓存 | 符合现有项目架构，减少依赖和团队学习成本。 |
| 是否按太阳系绝对真实比例显示 | 真实参数输入 + 统一非线性显示压缩 | 绝对比例下行星不可见，教学界面无法操作。 |
| 天体自转如何表示 | 等距柱状纹理球面采样 + 经度偏移 | 比直接旋转图片或绘制箭头更接近表面自转。 |
| 光照是否随纹理转动 | 光照方向固定，按球面法线重新计算 | 太阳照射方向不应跟随行星纹理旋转。 |
| 土星环如何支持全方位观察 | 透明环纹理 + 环平面投影 + 前后分层 | 保持环的纹理、开合角和球体遮挡关系。 |
| 探访时是否继续推进太阳系 | 冻结自动运动并隐藏其他天体 | 避免聚焦单颗天体时出现不符合观察逻辑的背景运动。 |
| 总览、平移和球体旋转如何区分 | 命中区域和输入状态机分流 | 让操作结果与用户按下的位置一致。 |
| 地表天空如何计算 | 三维黄道坐标→赤道坐标→地平坐标 | 比二维画面位移更能表达观察地点和时间关系。 |
| 彗星物理和画面是否使用同一偏心率 | 物理参数真实，视觉轨道单独压缩 | 保留速度与距离规律，同时避免近日点画面重叠。 |
| 团队皮肤类型冲突如何处理 | 保留原类型并增加独立渲染类型 | 不修改其他成员业务场景，降低集成风险。 |

### 6.2 科学性与教学表达

本项目是面向儿童的天文教学演示，不是精密天体力学仿真。行星公转周期、相对轨道距离、相对半径、地月父子关系、球面光照方向、哈雷彗星高偏心率运动和地表坐标转换保留了核心科学关系；天体绝对尺寸、绝对距离、自转展示周期、轨道倾斜画法和彗星视觉轨道经过教学压缩。界面不把压缩后的像素距离描述为真实测量结果，而是通过统一映射帮助儿童同时观察全部天体和交互效果。

### 6.3 AI 使用原则

- AI 用于辅助检查仓库、生成代码和文档初稿、实现数学计算、执行验证命令和整理修改记录。
- 本人负责确定需求、模块边界、科学表达、视觉取舍、手势规则和最终采用方案。
- AI 初稿必须经过编译、状态检查和浏览器实际运行后才能采用。
- 对平面贴图滚动、自转箭头、中轴线、错误手势和破坏其他成员素材接口的方案不直接采用。
- 团队集成时优先增加兼容层，不通过覆盖其他成员已完成的业务代码解决冲突。
- 最终成果以当前仓库代码、Git 记录、测试结果和实际页面表现为准。

### 6.4 个人总结

- 本人完成的主要工作：公共 Canvas 动画架构、太阳系自转公转、球面纹理与光照、土星环、通用天体探访、Arcball 和多端交互、地球地表视角、哈雷彗星模拟及共享接口文档。
- 开发过程中遇到的主要问题：真实比例与教学可见性的冲突、平面纹理缺少球面感、高分辨率采样性能、探访手势冲突、土星环遮挡、地表坐标关系和团队素材类型冲突。
- AI 提供的主要帮助：快速生成公共架构和数学实现初稿，辅助定位 Canvas 渲染和状态问题，批量整理测试及文档。
- 本人完成的关键修改：确定真实参数与显示映射分离、否定抽象自转方案、设计探访冻结和手势分流、调整球面缓存性能、保护其他成员场景并建立兼容接口。
- 后续仍可继续改进的内容：完成更多真机性能数据记录、增加低性能设备自动降级、补充无障碍键盘提示和开展儿童用户可用性测试。
