## 一、产品设计过程

### 1.1 负责内容

本人主要负责：

- 分析儿童用户特点，整理产品定位、信息结构和用户操作流程。
- 设计并实现日食、月食的全景视角和地球视角教学动画。
- 设计并实现太阳磁场、地球磁场及两者关系的动态演示。
- 检查专题场景与换肤、播放、暂停、重置、响应式布局等公共功能的兼容性。
- 编写和维护成员1相关产品、协作、流程及模块说明文档。

### 1.2 功能目标

- 通过太阳、地球和月球的位置及遮挡关系，帮助儿童理解日食和月食的形成。
- 通过地球公转、太阳和地球自转以及动态磁力线，表现磁场随天体运动发生的视觉变化。
- 使用简短提示、明显按钮和有限的模式选择降低儿童的理解与操作成本。
- 保证卡通和写实模式下的专题动画均能正确显示，并适配电脑和手机屏幕。
- 复用团队公共 Canvas 运行时，使专题场景与主界面的播放状态、速度和场景切换规则保持一致。

### 1.3 初步设计方案

- 页面入口：首次打开先进入欢迎页，点击“开始探索”后进入太阳系运行主界面，再通过底部“日食/月食”和“磁场”按钮进入专题场景。
- 主要天体或元素：太阳、地球、月球、月球轨道、阴影区域、磁极、磁轴、磁力线、太阳风粒子。
- 用户操作：切换日食/月食、全景/地球视角、磁场对比/太阳磁场/地球磁场，并使用公共播放、暂停、速度、换肤、缩放和重置控制。
- 动画表现：月球在轨道对齐位置附近运动；地球沿椭圆轨道绕太阳公转；太阳、地球及其磁场元素随时间变化。
- 预期学习效果：儿童能够通过画面理解日月食的三体对齐关系，并区分太阳磁场、地球磁场和太阳风的基本作用。

## 二、用户分析过程

### 2.1 目标用户

- 主要用户：7—12 岁儿童，也可由科学课教师或家长辅助使用。
- 知识基础：可能认识太阳、地球和月球，但不一定理解磁极、磁力线等概念。
- 操作设备：电脑、平板和手机浏览器。
- 使用特点：更容易被动态画面、鲜明颜色和即时反馈吸引，不适合一次阅读大量专业文字。

### 2.2 用户需求

- 动画过程需要容易观察，天体位置和运动方向必须清楚。
- 操作按钮需要简单、尺寸合适，点击后立即产生反馈。
- 文字说明必须与实际动画一致，避免阶段提示与运动方向矛盾。
- 日食、月食和磁场概念应采用教学示意表达，不堆叠复杂公式。
- 卡通和写实皮肤应同步应用到背景及主要天体，不能在同一场景混用。
- 手机端说明面板不能遮挡主要天体、轨道或磁力线。
- 进入专题场景后应继承此前播放或暂停状态，减少意外操作。

### 2.3 可能出现的问题

- 月球若只做上下直线运动，用户难以理解其与轨道的关系。
- 全景与地球视角若使用不同方向或不同节奏，容易造成认知混乱。
- 阴影透明度或尺寸处理不当，会让日食遮挡关系显得不真实。
- 写实 PNG 素材宽高比不同，直接缩放可能把太阳或月球拉成椭圆。
- 磁场画面元素较多，说明面板过大会在手机上遮挡磁力线。
- 专题场景若建立独立动画循环，可能与公共 Canvas 运行时争用资源。

### 4.2 具体修改说明

#### 4.2.1 调整月球运动轨迹与日月食表达

- 原始问题：初始月球采用上下直线移动；改为轨道后又出现全景绕行整圈、两个视角运动含义不统一的问题。
- 发现方式：在电脑浏览器中连续播放日食和月食，并对比全景视角与地球视角。
- 涉及文件：`src/canvas/scenes/eclipseScene.ts`
- 涉及模块：日食与月食场景
- 涉及函数或接口：`drawOverview`、`drawEarthView`、`drawMoonOrbit`
- 学生修改内容：
  1. 提出月球必须位于轨道上运动，不能继续使用上下直线位移。
  2. 将完整绕行整圈改为对齐位置附近的小范围曲线运动。
  3. 统一全景和地球视角的开始、中间、结束状态。
  4. 删除与实际方向不一致的“开始接近”和“逐渐离开”文字。
- 修改原因：日月食专题的教学重点是三天体短时间内的对齐过程，而不是完整展示月球公转周期。
- 修改结果：月球沿轨道曲线在关键位置附近移动，两个视角表达一致且更易理解。
- 验证方式：分别播放日食、月食及两个视角，检查多个动画进度下月球位置和遮挡关系。

#### 4.2.2 修复写实素材与日食遮挡

- 原始问题：写实月球被拉成长椭圆并出现三个红色斑块；地球视角的黑色月球剪影仍能看到内部纹理。
- 发现方式：切换写实皮肤后截图对比，并在日食地球视角观察遮挡边缘和内部明暗。
- 涉及文件：`src/canvas/scenes/eclipseScene.ts`、`src/canvas/scenes/sceneVisuals.ts`
- 涉及模块：日月食场景、公共天体素材绘制
- 涉及函数或接口：`drawEarthView`、`drawMoon`、`drawSkinnedBody`
- 学生修改内容：
  1. 要求月球使用相同绘制宽度和高度并通过圆形区域裁剪。
  2. 移除写实素材上额外叠加的红色装饰斑块。
  3. 将日食地球视角的月球剪影改为完全不透明的纯黑圆形。
  4. 检查卡通和写实皮肤使用各自对应的太阳、地球、月球及背景素材。
- 修改原因：天体形状和遮挡关系是日食教学的核心，错误比例与半透明纹理会误导用户。
- 修改结果：写实月球保持圆形且表面正常，日食剪影内部完全黑色。
- 验证方式：切换两种皮肤，进入日食和月食的两个视角逐项截图检查。

#### 4.2.3 增加动态磁场演示

- 原始问题：初版磁场页面主要展示两个静止天体和磁力线，未充分实现“磁场随天体运动变化”。
- 发现方式：播放磁场场景时观察，发现太阳、地球和整体位置几乎没有可辨识变化。
- 涉及文件：`src/canvas/scenes/magneticScene.ts`
- 涉及模块：太阳与地球磁场场景
- 涉及函数或接口：`update`、`drawComparison`、`drawDipoleField`、`drawSolarWind`、`drawOrbitPath`、`drawRotationCue`
- 学生修改内容：
  1. 明确提出只需太阳与地球的关系动画，不绘制完整太阳系。
  2. 增加地球沿椭圆轨道绕太阳公转，并绘制轨道和运行提示。
  3. 增加太阳与地球自转提示，使天体运动能够被直接观察。
  4. 让磁极、磁轴、磁力线和粒子随天体位置及时间变化。
  5. 让太阳风方向依据太阳与地球的相对位置更新。
- 修改原因：原效果只能说明磁场“存在”，不能表现任务要求中的动态变化。
- 修改结果：播放时可同时观察地球公转、天体自转、磁场变化和太阳风传播方向。
- 验证方式：在播放和暂停状态之间切换，观察天体、轨迹、磁力线与粒子是否同步变化或停止。

#### 4.2.4 修复写实太阳比例和播放状态

- 原始问题：写实太阳图片在旋转后呈椭圆形；进入磁场专题时动画状态可能与主场景不一致。
- 发现方式：在写实皮肤中播放磁场动画，并分别从播放和暂停状态进入专题场景。
- 涉及文件：`src/canvas/scenes/sceneVisuals.ts`、`src/canvas/scenes/magneticScene.ts`、`src/canvas/scenes/registerMember1Scenes.ts`
- 涉及模块：公共素材绘制、磁场场景、场景注册
- 涉及函数或接口：`drawSkinnedBody`、`createMagneticScene`、`CanvasRuntime`
- 学生修改内容：
  1. 将写实太阳图片进行居中裁切，绘制区域固定为正方形。
  2. 使用圆形裁剪路径限制天体边界，在旋转时仍保持圆形。
  3. 要求专题场景沿用公共播放状态，不在进入场景时自动播放或暂停。
  4. 验证重置只重置当前专题，返回主界面由“太阳系总览”入口完成。
- 修改原因：保证视觉比例正确，并使全项目的播放控制具有统一、可预测的行为。
- 修改结果：写实太阳始终保持圆形，场景切换前后的播放状态一致。
- 验证方式：在两种播放状态和两种皮肤下反复切换太阳系总览与磁场场景。

#### 4.2.5 优化手机端磁场说明面板

- 原始问题：手机竖屏中“太阳磁场”等说明面板占用面积过大，遮挡部分磁力线和天体动画。
- 发现方式：使用手机通过局域网访问页面并截图检查。
- 涉及文件：`src/canvas/scenes/magneticScene.ts`
- 涉及模块：磁场场景响应式绘制
- 涉及函数或接口：`drawInfoPanel`、紧凑布局分支
- 学生修改内容：
  1. 缩小说明卡片宽度和高度。
  2. 减少标题、正文的字号、行距和内边距。
  3. 调整卡片位置，为主要磁场动画保留更多空间。
- 修改原因：移动端画布较窄，说明信息应辅助教学而不能盖住核心动画。
- 修改结果：手机端说明仍可阅读，同时磁场主体和磁力线显示更加完整。
- 验证方式：在手机竖屏中切换磁场对比、太阳磁场和地球磁场三种模式检查。

### 4.3 人工修改与 AI 生成内容的区别

## 五、用户体验优化过程

### 5.1 测试方式

- 在 Chrome 和 Edge 中打开本地页面，检查刷新、缓存和运行效果。
- 使用手机通过同一局域网访问页面，检查竖屏布局和触控区域。
- 分别测试卡通与写实皮肤，检查背景和太阳、地球、月球素材。
- 测试日食/月食、全景/地球视角和三种磁场模式。
- 测试播放、暂停、速度、重置、返回总览及场景切换。
- 执行 TypeScript 构建并检查浏览器运行期间是否出现错误。

### 5.2 体验问题与优化

| 体验问题 | 优化方式 | 最终效果 |
| --- | --- | --- |
| 月球直线运动或整圈绕行使教学重点不清楚 | 改为轨道对齐位置附近的小范围曲线运动 | 日月食形成过程更直观。 |
| 时间轴阶段文字与运动方向不一致 | 删除容易造成误解的阶段文字 | 说明与动画不再冲突。 |
| 写实素材比例和遮挡显示错误 | 使用等宽高绘制、居中裁切、圆形遮罩及纯黑剪影 | 天体保持圆形，遮挡关系清晰。 |
| 磁场对比缺少明显运动 | 增加公转、自转、轨迹和动态磁场元素 | 能够观察磁场随天体运动变化。 |
| 手机端说明卡遮挡动画 | 缩小卡片、字体和间距并重新定位 | 主要磁场动画得到更多显示空间。 |
| 场景切换后播放状态突变 | 统一由 `CanvasRuntime` 管理播放状态 | 用户操作连续且可预测。 |

### 5.3 优化结果

- 操作清晰度：专题入口、模式按钮、重置和返回总览的职责更加明确。
- 动画可理解性：日月食集中表现关键对齐过程，磁场场景具有可观察的动态变化。
- 页面美观度：卡通与写实素材保持一致，写实天体不再拉伸或出现错误叠加图形。
- 手机端适配：说明面板占用空间减少，主要动画和触控区域保留完整。
- 运行稳定性：专题场景复用统一动画循环和播放状态，不创建额外 `requestAnimationFrame`。

## 六、设计决策说明

### 6.1 主要设计决策

| 设计问题 | 最终选择 | 选择原因 |
| --- | --- | --- |
| 是否设置独立“开始探索”页面 | 设置欢迎页，点击“开始探索”后进入太阳系主界面 | 先完成素材初始化并用清晰入口降低儿童的认知负担。 |
| 全景月球是否完整绕地球一圈 | 只在对齐位置附近做小范围曲线运动 | 日月食专题关注对齐和遮挡，不需要演示完整公转周期。 |
| 地球视角日食剪影是否保留月球纹理 | 使用完全不透明的黑色剪影 | 更准确地表达逆光遮挡，并避免纹理透出造成视觉错误。 |
| 磁场场景是否展示整个太阳系 | 只展示太阳和地球及其相对运动 | 减少无关信息，让用户集中观察太阳风与两种磁场。 |
| 专题是否建立独立动画循环 | 复用 `CanvasRuntime` 和统一 `requestAnimationFrame` | 避免多个循环争用 Canvas，并统一播放、暂停和速度控制。 |
| 写实天体如何保持圆形 | 居中裁切、等宽高绘制并增加圆形遮罩 | 原始图片宽高比不同，直接拉伸会破坏天体形状。 |

### 6.2 科学性与教学表达

日月食和磁场动画属于面向儿童的教学示意，并非天文或电磁学精确仿真。天体尺寸、距离、运行速度、磁力线密度和太阳风粒子均经过视觉缩放。设计时保留日月食的基本对齐与遮挡关系、地球绕太阳公转、天体自转、磁极和磁力线等核心概念，同时省略真实比例和复杂公式，使儿童能够先理解现象之间的关系。文档和界面中不将这些示意数据描述为精确物理计算结果。

### 6.3 AI 使用原则

- AI 用于辅助检查仓库、生成代码和文档初稿、修改实现及执行验证命令。
- 本人负责提出需求、判断实际效果、发现问题并决定最终采用方案。
- AI 初稿必须经过浏览器实际运行、不同设备和不同皮肤测试后才能采用。
- 未被采用的完整绕轨方案、错误阶段文字和有问题的素材显示不作为最终成果。
- 最终内容以项目代码、Git 提交记录和实际运行效果为准。

### 6.4 个人总结

- 本人完成的主要工作：产品和用户流程设计，日食/月食专题、太阳与地球磁场专题，以及相关换肤、响应式和文档维护。
- 开发过程中遇到的主要问题：月球轨迹与教学过程不一致、写实素材比例异常、日食遮挡不正确、磁场动画变化不明显、手机端信息面板遮挡。
- AI 提供的主要帮助：快速理解团队公共接口，生成 Canvas 场景基础代码，辅助修改动画计算和整理说明文档。
- 本人完成的关键修改：根据浏览器和手机实际效果重设月球运动、磁场动态、素材裁切、播放状态和移动端布局。
- 后续仍可继续改进的内容：增加更清晰的磁场变化图例、完善无障碍操作，并邀请真实儿童用户进行可用性测试。
