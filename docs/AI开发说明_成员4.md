## 二、产品设计与用户分析

### 2.1 目标用户

主要用户是5至12岁儿童：

- 注意力保持时间较短，需要快速反馈。
- 更容易理解可拖动、可切换和持续运动的视觉内容。
- 对颜色、图形和明确的选中状态比较敏感。
- 不适合阅读长段落或复杂参数。

辅助用户是教师和家长：

- 需要稳定、可重复的演示流程。
- 需要暂停、调速、切换视角和恢复默认状态。
- 需要科学表述清楚，不能把教学近似写成真实物理仿真。

### 2.2 成员4相关用户问题

| 用户问题 | 对应设计 |
| --- | --- |
| 刷新后设置丢失 | 使用LocalStorage统一保存语言和皮肤 |
| 学习过程没有反馈 | 记录已访问行星和已完成任务 |
| 英文界面不适合儿童 | 使用短句、稳定术语和中英文同键词典 |
| 太阳风难以理解 | 拆成向外辐射、磁层屏障、极区互动三种模式 |
| 小游戏在不同设备难度不一致 | 按视口短边归一化拖动距离 |
| 轻触就被判定完成 | 只有达到大变化并松开后才结算 |
| 移动端按钮过多 | 小屏图标化并分三排，保持40像素触控尺寸 |

### 2.3 操作步骤控制

成员4两个主要流程均不超过5步：

太阳雨入口下的太阳风演示：

1. 点击“太阳雨”。
2. 选择向外辐射、磁层屏障或极区互动。
3. 使用播放、暂停或速度控制观察变化。

轨道小游戏：

1. 点击“轨道小游戏”。
2. 按住地球拖动。
3. 松开查看变化等级和得分。
4. 点击重置开始下一次尝试。

## 三、关键设计决策

| 问题 | 最终选择 | 原因 |
| --- | --- | --- |
| Storage结构 | 单一版本化根键 | 便于整体读取、升级、回退和清空 |
| 天体与任务标识 | 稳定英文ID | 不受显示语言变化影响 |
| Storage不可用 | 保留会话内状态 | 浏览器禁用存储时主功能仍可运行 |
| 词典加载失败 | 回退内置中文核心词典 | 避免页面初始化失败 |
| 英文缺失键 | 英文回退中文，再回退键名 | 不显示`undefined` |
| 小游戏模型 | 拖动距离教学近似 | 可理解、可测试，不冒充真实引力计算 |
| 小游戏结算 | 仅大变化、松开后、每局一次 | 防止轻触、小拖动和重复事件污染记录 |
| 太阳风模型 | 概念粒子动画 | 解释传播和偏转，不伪造实时空间天气数据 |
| 动画调度 | 使用团队公共Canvas运行时 | 避免第二个`requestAnimationFrame` |
| 太阳风入口协议 | 服从最新`dev`的“太阳雨”协议 | 避免重复按钮和事件冲突 |
| 美术素材 | 复用团队已有天体素材 | 保持风格统一并减少版权风险 |
| 构建输出 | 使用`dist/` | 避免生成JS污染`src/`并被测试误加载 |

太阳风科学表达边界：

- 向外辐射表示太阳向行星空间释放带电粒子。
- 磁层屏障表示多数粒子被地球磁场改变路线。
- 极区互动表示少量粒子可能沿磁力线进入极区。
- 动画不提供真实速度、密度或空间天气预报。

小游戏科学表达边界：

- 得分来自拖动距离和教学阈值。
- 轨道形状是变化反馈，不是数值积分结果。
- 页面不得宣称它是精确引力模拟。

### 4.2 LocalStorage约定

唯一根键：

```text
solarkids.user-state.v1
```

当前状态结构：

```ts
interface SolarKidsUserState {
  version: 1;
  language: 'zh-CN' | 'en';
  skinId: string;
  learningProgress: {
    visitedPlanetIds: string[];
    completedTaskIds: string[];
  };
  gameRecord: {
    playCount: number;
    successCount: number;
    bestScore: number;
    lastScore: number;
  };
}
```

默认值：

- 语言：`zh-CN`
- 皮肤：`cartoon`
- 学习记录：空数组
- 游戏次数和分数：0

公开接口位于`src/storage/index.ts`：

- `loadUserState()`、`saveUserState()`
- `updateUserState()`、`resetUserState()`
- `setLanguage()`、`setSkin()`
- `markPlanetVisited()`、`markTaskCompleted()`
- `saveGameResult()`
- `UserStateStore`

Storage模块负责：

- 补全旧数据缺失字段。
- 拒绝不支持的数据版本。
- 规范化语言、分数、天体ID和任务ID。
- 数组去重。
- 捕获读写异常并保持应用可用。

UI和Canvas模块不得自行解析LocalStorage JSON，应调用上述接口。

### 4.3 多语言约定

词典文件为`src/data/language.json`，当前中英文各215个同名键。

加载和回退流程：

1. 浏览器异步加载JSON。
2. 校验`zh-CN`和`en`均为非空字符串字典。
3. 校验两个字典的键完全一致。
4. 加载失败时使用内置中文核心词典。
5. 当前语言缺键时先回退中文，再显示键名。

主要接口：

- `loadTranslationData()`
- `I18nService.translate()`
- `I18nService.hasTranslation()`
- `createMember4Integration()`
- `applyDocumentLanguage()`
- `localizeInfo()`

HTML使用以下属性接入：

- `data-i18n`
- `data-i18n-title`
- `data-i18n-aria-label`

稳定ID、数据字段和DOM事件不翻译，只翻译用户可见文字和无障碍标签。

### 4.5 公共场景协议

成员4场景由`registerMember4Scenes()`统一注册：

| 用户入口 | 按钮ID | DOM事件 | 场景ID |
| --- | --- | --- | --- |
| 太阳雨 | `btn-solar-rain` | `solarkids:showSolarRain` | `solar-rain` |
| 轨道小游戏 | `btn-orbit-game` | `solarkids:showOrbitGame` | `orbit-game` |

`solar-rain`是成员3在最新`dev`中确定的公共协议。成员4把太阳风教学动画接到
该场景，不再注册旧的`solar-wind`场景，不再增加`btn-solar-wind`按钮。

两个场景均遵守`CanvasScene`生命周期：

- `enter()`绑定自身事件。
- `render()`使用公共Canvas绘制。
- `reset()`恢复场景状态。
- `exit()`移除指针和键盘监听器。
- 不创建独立动画循环。

### 4.6 太阳风场景

场景包含三种模式：

| 模式 | 教学内容 |
| --- | --- |
| `radial` | 粒子从太阳向外传播 |
| `shield` | 多数粒子在地球磁层前方偏转 |
| `aurora` | 少量粒子沿磁力线进入极区 |

粒子状态更新使用公共`frame.deltaMs`，因此自动受播放、暂停和速度倍率控制。
太阳和地球贴图使用团队当前皮肤素材。

### 4.7 轨道小游戏

纯逻辑阈值：

| 归一化拖动距离 | 等级 | 分数 | 是否完成 |
| --- | --- | --- | --- |
| `0`至`5` | `stable` | 0 | 否 |
| 大于`5`且小于`60` | `small` | 50 | 否 |
| 大于等于`60` | `large` | 100 | 是 |

Canvas场景将不同设备的拖动距离归一化到500单位范围，避免同一比例手势在PC和
手机得到不同结果。

结算规则：

1. 只有`large`状态才算完成。
2. 只有松开或取消指针时检查结算。
3. 每次重置前最多保存一次。
4. 成功后记录任务`orbit-game-large-change`。
5. 轻触和小变化不增加`playCount`。
